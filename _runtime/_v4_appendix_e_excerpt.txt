## 附录 F · 线上取证 SOP（每次报缺陷先跑这四步）

```bash
# 1. 确认在跟哪个产物对话（INV-16）
docker ps --digests
docker inspect -f '{{.Created}} {{.Image}} {{.Config.Image}}' <cid>
curl -s http://127.0.0.1:8080/healthz | jq .

# 2. 抓原始字节，不经 SDK / jq / 网关
curl --raw -N -s -D headers.txt http://127.0.0.1:8080/v1/chat/completions \
  -H "Authorization: Bearer $KEY" -H 'Content-Type: application/json' \
  -d '{"model":"<alias>","stream":true,"messages":[{"role":"user","content":"<能复现的那句>"}]}' \
  | tee raw.sse

# 3. 判别方言与编码：竖线是 7C 还是 EF BC 9C，下划线是不是 E2 96 81
xxd raw.sse | grep -i -m5 -B1 -A1 'tool'
tail -c 2000 raw.sse | cat -A | tail -40      # 看末尾三个数据行与终止信号

# 4. 三层对齐（决定性的一刀）
#    上游原始流（REQ-OBS-07 落盘）vs 本服务输出 vs 客户端所见
#    - 上游有完整答案、本服务没有 -> 净化层吞了（查 INV-03 / INV-13 / REQ-SAN-15）
#    - 上游也是一两句就停   -> 上游侧，唯一 bug 是你把它映射成了 stop（INV-11 / INV-17）
diff <(python scripts/replay.py --fixture new.raw --mode stream) \
     <(python scripts/replay.py --fixture new.raw --mode nonstream)
```
